# Remaining Weeknotes operator composition

Preserve the remaining four original workflows: install-epoch, rollback,
rotate-auth and guarded reconcile-enable. The five explicit identity actions
stay unchanged. No actual app, posts, auth rotation or schedule is executed for
qualification. Timer retirement and existing confirmations remain business
rules; add no owner acknowledgement or permanent Ansible exception.

## Private composition

Use normal CLI prepared Sessions registrations and one Main context per explicit
invocation. Build temporary copied inventory variable mappings for the original
`daybook_weeknotes_post_identity_epoch_requested` and
`daybook_weeknotes_reconcile_pi_auth_rotate_requested`; never mutate inventory
or global registrations. Retain general Sessions activation refusal.

Preserve each convenience recipe's exact original order and prompt. Install
epoch: existing disabled install, verify, apply, then disabled Sessions install
with requested `monday-after-v1`. Rollback: emergency disable then ordinary
disabled Sessions install, allowing the original retired-unit default to retain
the required epoch: on current retired=true inventory the resulting epoch stays
`monday-after-v1`, its exact environment line is retained and the dedicated
plist stays absent with its unit disabled/unloaded. On non-retired inventory
the original empty requested/default epoch is preserved in the disabled
installation. Rotation: original y/N, emergency disable, then full disabled
Sessions deploy with rotate requested true. Rotation does not stop the separate
operations source; existing outside-run guidance remains documented.

Enable: first preserve the exact strict false-or-unset inventory retirement
guard before source, secret or transport work. Read the same repository-root
inventory context as original ansible-inventory. Keep original y/N, disable,
disabled install, idempotent apply, disabled epoch install, then the separate
fresh same-run verified-apply activation rail with original exact ENABLE phrase.
All engine lookups honor METADATA_FILE. Keep explicit original fallback.

## Public activation rail

Add a small separate activation API with original fixed owner/path/label,
required Main, hidden ordered intent and exact
`ENABLE monday-after-v1 draft schedule` confirmation. Require retired flag
strictly false. Reuse the five-action identity config fixed relationships and
original apply phrase internally as the original activation play does.

The activation deploy clears all seven inherited privilege fields, requires
Darwin/original root, and executes the qualified system disable before one
managed sequence. Reuse the installed-package identity host implementation;
introduce an optional after-verified callback into its internal execute function
so activation can bind the fresh private plan hash in the same remote process.
Activation loads the packaged identity helper as an embedded named module
(`__name__` is not `__main__`), so its stdin-reading main does not execute;
a separate activation main owns protected input and calls execute with the
trusted packaged callback. Existing five-action entry points pass no callback
and retain their output/ordering. Their embedded helper bytes do change, so
re-qualify the full existing nineteen-case native identity fixture against the
new immutable Git artifact; do not claim its old payload is byte-identical.
No raw hash crosses the protected target process boundary.

After successful apply and verify with equal plan hashes and original root
proof publication or exact existing-proof reuse, the callback always re-reads
and compares that proof with the fresh same-run plan hash and Main, independently
of `proof_written`. It enforces original safe single-link regular
owner/mode metadata for environment, root proof, checksum, reconcile launcher
and system plist. Compare the exact epoch environment line and root proof
against the fresh required Main and plan hash in RAM. Require original unit
disabled/unloaded, then launchctl enable and bootstrap exact plist, with no
kickstart. Verify loaded and persistently enabled result. Retain the original
schedule and RunAtLoad=false declaration; do not run reconciliation.

Preserve original partial activation effects instead of inventing rollback:
if enable succeeds but bootstrap fails, or bootstrap succeeds but final checks
fail, emit distinct fixed content-free phase categories. Do not collapse these
into a pre-enable refusal or claim the timer remains disabled. Document exact
recovery through the existing emergency disable recipe. Native controls must
prove actual enabled/unloaded state after bootstrap failure and actual loaded
state after verification failure, then owned cleanup. A fixture-only owned
launchctl proxy may inject these exact failures while forwarding successful
commands to real launchctl; production declaration fixes /bin/launchctl and
fixtures disclose their unvalidated substitution.
